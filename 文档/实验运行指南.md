# 实验运行指南

## 环境要求

- Python 3.11 或更高版本。
- 一个 OpenAI-compatible Chat Completions API。
- API key 通过环境变量或命令行传入，不要写进代码。

安装依赖：

```bash
python -m pip install -r requirements.txt
```

当前实验运行依赖很少：`pandas` 用于读取和处理 PitchBook 表格，`openpyxl` 用于让 `pandas.read_excel()` 读取 `.xlsx/.xlsm` 工作簿。LLM 请求使用 Python 标准库 `urllib`，不需要额外安装 OpenAI SDK。

默认模型配置仍可通过命令行覆盖。代码会读取：

- `BOARDROOM_LLM_API_KEY`
- `BOARDROOM_LLM_MODEL`
- `BOARDROOM_LLM_BASE_URL`
- `BOARDROOM_LLM_TEMPERATURE`
- `BOARDROOM_LLM_TIMEOUT_SECONDS`
- `BOARDROOM_LLM_HTTP_MAX_RETRIES`
- `BOARDROOM_LLM_RETRY_BASE_SECONDS`

## 批量实验

```bash
python run_batch_experiments.py \
  --input input/260524_02_03_pitchbook_sample_100_shared.xlsx \
  --output-dir outputs/batch/smoke_test \
  --config configs/boardroom_default.toml \
  --repeats 1 \
  --case-limit 3
```

批量运行会自动生成：

- 每个 run 的 `results.jsonl`
- 每个 run 的 `traces.json`
- 每个 run 的 `metrics.json`
- 每个 run 的 `case_metrics.csv`
- 每个 run 的 `debate_accuracy_report.md`
- 每个 run 的两个 baseline 结果和指标
- 总体 `aggregate_metrics.json`
- 总体 `case_metrics.csv`

中断后恢复：

```bash
python run_batch_experiments.py \
  --input input\260524_02_03_pitchbook_sample_100_shared.xlsx \
  --output-dir outputs/batch/smoke_test \
  --config configs/boardroom_default.toml \
  --resume
```

跳过详细 trace：

```bash
--skip-traces
```

跳过 baseline：

```bash
--skip-baselines
```

## 新建一个实验配置

建议复制默认配置：

```bash
copy configs\boardroom_default.toml configs\my_experiment.toml
```

然后修改：

```toml
[experiment]
name = "my_experiment"
# 兼容旧字段；当前表示最大讨论轮数。
bargaining_rounds = 4
history_limit = 5

[discussion]
protocol = "chair_gated"
memory_scope = "full"
response_generator = "reasoning"
min_rounds = 2
max_rounds = 4
stop_when_consensus_score_gte = 0.82
stop_when_no_role_changes_for_rounds = 1
stop_when_no_open_questions = true
round_tasks = [
  "第 1 轮：只讨论交易类型和融资规模。",
  "第 2 轮：只讨论估值方向和投资人持股比例。",
  "第 3 轮：回应开放问题并提出必要修正。",
  "第 4 轮：形成最终支持、反对或保留意见。",
]

[decision.weights]
Founder_CEO = 2.0
CTO = 0.5
Lead_VC_Director = 3.0
Followon_VC_Director = 1.5
```

运行时指定：

```bash
python run_batch_experiments.py \
  --input input/260524_02_03_pitchbook_sample_100_shared.xlsx \
  --output-dir outputs/batch/my_experiment \
  --config configs/my_experiment.toml \
  --repeats 1
```

## 配置董事会过程

优先只改 `board.archetype`：

```toml
[board]
archetype = "value_creating"
```

四种 archetype 会默认带出 L5 文化层、会议阶段、讨论协议、主导模式、挑战要求、记忆范围和角色权重乘数。L5 的 0-1 数值会先由代码解释为强度等级、行为规则和控制参数，例如最少证据锚点、挑战模式、替代方案要求和共识压力：

| archetype        | 文化/过程含义                | 默认过程效果                                           |
| ---------------- | ---------------------------- | ------------------------------------------------------ |
| `aunt`           | 形式化、被动确认、管理层主导 | `rubber_stamp`，低挑战，有限记忆，Founder CEO 权重更高 |
| `barbarian`      | 控制、监督、低信任、高批判   | `top3_dominance`，强制挑战，Lead VC 权重更高           |
| `clan`           | 高亲近、高信任、重共识       | `chair_gated`，不强制挑战，Founder CEO 权重略高        |
| `value_creating` | 监督和支持并重，开放异议     | `free_interjection`，强制建设性挑战，权重保持均衡      |

如需做消融实验，可以只覆盖某些字段：

```toml
[board]
archetype = "value_creating"

[board.culture]
criticality = 0.75
creativity = 0.70
cohesiveness = 0.70
openness_generosity = 0.80
preparation_involvement = 0.85

[board.role_weight_multipliers]
Founder_CEO = 1.0
CTO = 1.0
Lead_VC_Director = 1.0
Followon_VC_Director = 1.0

[discussion]
protocol = "chair_gated"
challenge_required = true
memory_scope = "full"
memory_window = 10
min_rounds = 2
max_rounds = 6
stop_when_consensus_score_gte = 0.82
stop_when_no_role_changes_for_rounds = 1
stop_when_no_open_questions = true
```

当前 `protocol` 支持：

- `chair_gated`：固定顺序发言。
- `free_interjection`：每轮轮换顺序，模拟开放插话。
- `top3_dominance`：有效权重最高的前三位角色发言。
- `rubber_stamp`：第一轮由 Founder CEO 和 Lead VC 框定议案，后续轮次以投资人形式澄清和管理层/Lead VC 确认为主。

当前 `archetype` 支持：

- `value_creating`
- `aunt`
- `barbarian`，兼容旧别名 `barbarian_control`
- `clan`，兼容旧别名 `clan_consensus`

`archetype` 会改变 L5 文化层、会议阶段、讨论过程和角色有效权重。trace 中会记录 `board_process`、`process_context`、`meeting_artifacts`、`base_role_weights` 和 `effective_role_weights`。

## 常见修改

### 改角色可见字段

修改对应文件：

```text
policies/roles/founder_ceo.toml
policies/roles/cto.toml
policies/roles/lead_vc_director.toml
policies/roles/followon_vc_director.toml
```

字段在：

```toml
layer_2_attention_fields = [
  "prior_deal_size_usd_m",
  "employee_growth_rate",
]
```

字段名必须来自 `BoardCase.to_dict()`。不要加入真实标签字段。

### 改每轮讨论流程

修改配置：

```toml
[discussion]
min_rounds = 2
max_rounds = 6
stop_when_consensus_score_gte = 0.82
stop_when_no_role_changes_for_rounds = 1
stop_when_no_open_questions = true

round_tasks = [
  "第 1 轮：...",
  "第 2 轮：...",
  "第 3 轮：...",
]
```

讨论现在不是固定三轮。模拟器会至少运行 `min_rounds`，最多运行 `max_rounds`；每轮后根据角色预测是否变化、是否有开放问题、共识分数是否达到阈值来决定是否继续。

`--bargaining-rounds` 仍然可用，但现在表示覆盖最大讨论轮数。`max_rounds` 如果大于 `round_tasks` 数量，后续轮次会复用最后一条任务。

### 改 prompt 文案

直接修改：

```text
prompts/system_agent.md
prompts/initial_prediction.md
prompts/bargaining_step.md
prompts/baseline_system.md
prompts/baseline_single_agent.md
```

注意不要删除模板变量，例如 `$observed_fields_json`、`$proposal_json`。

### 新增发言风格

新建：

```text
prompts/response_generators/my_style.md
```

配置：

```toml
[discussion]
response_generator = "my_style"
```

## 单个样例运行并输出可读董事会过程

如果希望先检查单个样例的董事会模拟是否符合实际，可以使用 `run_experiment.py`，并通过 `--case-limit 1` 只运行一个案例。新增的 `--readable-output` 会生成 Markdown 文本报告，记录背景、流程设置、角色初始判断、每轮发言、观点变化、会议行为字段、最终聚合结果和真实标签对照。

```bash
export BOARDROOM_LLM_API_KEY="sk-1f653be29e314b1da4028b4c3a8de0b0"
```

```bash
python run_experiment.py \
  --input input/260524_02_03_pitchbook_sample_100_shared.xlsx \
  --output outputs/one_case/results.jsonl \
  --trace-output outputs/one_case/traces.json \
  --readable-output outputs/one_case/boardroom_trace.md \
  --config configs/boardroom_default.toml \
  --case-limit 1 \
  --model deepseek-v4-pro \
  --base-url https://api.deepseek.com
```

如果已经有 `traces.json`，也可以事后单独生成可读报告：

```bash
python render_trace_report.py \
  --trace-json outputs/one_case/traces.json \
  --output outputs/one_case/boardroom_trace.md \
  --case-index 0
```
